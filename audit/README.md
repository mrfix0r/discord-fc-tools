# Discord Read-Only Audit

Безопасный экспорт структуры Discord-сервера для анализа и проектирования
воронки `Discord → Twitch`.

Скрипт использует только `GET`-запросы Discord API. Он не умеет создавать,
изменять или удалять каналы, роли, сообщения и участников.

## Что попадёт в обычный отчёт

- категории и каналы, их порядок и описания;
- ролевые ограничения каналов;
- роли и количество участников с каждой ролью, если Discord разрешит получить счётчики;
- дата последнего сообщения;
- количество сообщений и уникальных собеседников за выбранный период;
- помесячная динамика активности;
- настроенные события и Welcome Screen, если они доступны;
- названия серверных эмодзи.

Не попадут:

- токен бота;
- Discord ID и имена пользователей;
- тексты сообщений;
- ссылки на вложения;
- личные сообщения;
- история голосовых каналов.

## 1. Создать временного бота

1. Открой [Discord Developer Portal](https://discord.com/developers/applications).
2. Нажми **New Application** и назови приложение, например `FC Audit Reader`.
3. Открой раздел **Bot** и создай бота, если он ещё не создан.
4. Получи токен через **Reset Token** / **Copy**.
5. Никому не отправляй токен и не вставляй его в сообщения ChatGPT.

Для обычного отчёта включать **Message Content Intent** не требуется. Он нужен
только для необязательного режима с примерами текстов.

## 2. Пригласить бота на сервер

В разделе **OAuth2 → URL Generator**:

1. Выбери scope `bot`.
2. Оставь только разрешения:
   - `View Channels`;
   - `Read Message History`.
3. Перейди по созданной ссылке и выбери нужный сервер.

Не выдавай `Administrator`, `Manage Server`, `Manage Channels`, `Manage Roles`
или права на отправку сообщений.

Если бот не должен видеть приватную модераторскую категорию, не добавляй его
роль в разрешения этой категории. Для полного аудита остальных закрытых
категорий явно разреши его роли `View Channel` и `Read Message History`.

## 3. Узнать Server ID

1. В Discord открой **Настройки пользователя → Расширенные**.
2. Включи **Режим разработчика**.
3. Нажми правой кнопкой по значку сервера и выбери **Копировать ID сервера**.

## 4. Запустить в Windows

Нужен Python 3.10 или новее. Дополнительные библиотеки не требуются.

Распакуй архив, открой PowerShell в папке и выполни:

```powershell
.\run_audit.ps1 -GuildId "ID_СЕРВЕРА"
```

PowerShell попросит токен скрытым вводом. После завершения токен удаляется из
переменной окружения процесса.

Если Windows блокирует запуск `.ps1`:

```powershell
powershell -ExecutionPolicy Bypass -File .\run_audit.ps1 -GuildId "ID_СЕРВЕРА"
```

Отчёт появится рядом со скриптом:

```text
discord-audit-report.json
```

Загрузи этот JSON в текущий чат. По нему можно будет определить:

- какие Albion-категории сохранить как наследие FC;
- какие каналы архивировать или объединить;
- где раньше находилось активное ядро сообщества;
- как перестроить сервер под RF Online и воронку на стрим;
- какие роли и каналы уже можно использовать повторно.

## Настройки анализа

Проверить последние два года, но просматривать не больше 2000 сообщений в
каждом канале:

```powershell
.\run_audit.ps1 -GuildId "ID_СЕРВЕРА" -Days 730 -MaxMessagesPerChannel 2000
```

Чтобы получить только структуру без просмотра истории сообщений:

```powershell
.\run_audit.ps1 -GuildId "ID_СЕРВЕРА" -MaxMessagesPerChannel 0
```

### Необязательные примеры сообщений

Для первоначального аудита они не нужны. Если позже потребуется понять тематику
старых каналов, включи **Message Content Intent** на странице бота и запусти:

```powershell
.\run_audit.ps1 -GuildId "ID_СЕРВЕРА" -IncludeContent
```

В отчёт попадёт до 20 последних непустых сообщений каждого канала. Имена будут
заменены псевдонимами, а ссылки, телефоны, email и Discord-упоминания скрыты.
Перед загрузкой такого отчёта всё равно просмотри JSON самостоятельно.

## После аудита

Удалить временного бота можно через **Настройки сервера → Интеграции** или через
список участников. После удаления рекомендуется нажать **Reset Token** в
Developer Portal, чтобы старый токен перестал действовать.
