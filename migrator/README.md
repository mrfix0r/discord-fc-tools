# FC Discord Migrator

Готовая одноразовая автоматизация перестройки сервера **FC** под воронку «Discord → стрим» и будущий переход в **RF Online**.

По умолчанию программа работает только в режиме просмотра: получает актуальные каналы и роли через Discord API, проверяет конфликты и печатает план. Изменения применяются лишь с флагом `--apply` и контрольной фразой. Удаление каналов, ролей и сообщений в программе не реализовано.

## Что изменится

- `Общие` станет `FC // START`, а существующие приветствие, новости и роли получат понятные названия.
- Живой `🐒флуд` станет основной `🍻таверной`; история сообщений сохранится.
- `🎬stream-bot` станет `🔴эфиры`; существующий голосовой стрим-канал переедет в `FC // LIVE`.
- Появятся каналы для клипов, поиска группы и решений во время эфира.
- Появится компактный раздел `⚙️ RF ONLINE` с новостями, форумом, составом и голосовым каналом.
- Старые разделы Albion Online и Apex будут переименованы в архивы и скрыты от `@everyone`. Доступ останется через архивные роли и прежние точечные разрешения.
- Будут созданы роли интересов: эфиры, RF Online, состав FC, поиск группы и два архивных доступа.

Полный декларативный план находится в `migration_plan.json` — его можно отредактировать до применения.

## 1. Права временного бота

В Discord Developer Portal откройте приложение бота, затем пригласите его на сервер с правами:

- View Channels
- Read Message History
- Manage Channels
- Manage Roles

`Administrator` и Message Content Intent не нужны. Роль бота должна стоять **выше ролей, которые он будет переименовывать** (`FC old`, `Претендент`, `💪Претендент💪`). После проверки миграции права управления можно снять или удалить бота с сервера.

## 2. Сначала только проверка

Скопируйте `migration_plan.example.json` в `migration_plan.json`.
В локальной копии задайте `guild.expected_id` — ID вашего сервера; проверьте
`guild.expected_name` и весь план. Локальная копия исключена из Git.
В командах ниже замените `YOUR_DISCORD_SERVER_ID` тем же числовым ID.
Это сохранённый план перестройки FC от 04.09.2026: перед повторным применением
сверьте его с текущей структурой сервера.


Откройте PowerShell в папке комплекта. В классической консоли Windows скрытый ввод Python иногда не принимает `Ctrl+V` и правый клик. В этом случае сначала скопируйте токен в буфер обмена, затем выполните:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\run_migration.ps1 -GuildId "YOUR_DISCORD_SERVER_ID" -TokenFromClipboard
```

Лаунчер прочитает токен из буфера, сразу очистит буфер обмена и удалит временную переменную после завершения. Токен не отображается и не попадает в историю команд. В терминале появится `MIGRATION PREVIEW`; сервер не изменится.

Без буфера обмена можно запустить обычный скрытый ввод:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\run_migration.ps1 -GuildId "YOUR_DISCORD_SERVER_ID"
```

Если политика PowerShell уже разрешает локальные сценарии, короче:

```powershell
.\run_migration.ps1 -GuildId "YOUR_DISCORD_SERVER_ID"
```

Можно обойти PowerShell и запустить Python напрямую:

```powershell
py -3 .\discord_fc_migrator.py --guild-id YOUR_DISCORD_SERVER_ID
```

## 3. Применение

Только после внимательной проверки preview:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\run_migration.ps1 -GuildId "YOUR_DISCORD_SERVER_ID" -TokenFromClipboard -Apply
```

Введите контрольную фразу `MIGRATE FC`. Перед первым изменением программа сохранит приватный JSON-снимок в папку `backups`. Не публикуйте этот файл: в нём нет токена или содержимого сообщений, но есть ID объектов и матрица разрешений.

Повторный запуск безопасен: уже созданные роли и каналы распознаются по именам, а существующие объекты не дублируются.

## 4. Откат

Сначала посмотреть план отката:

```powershell
.\run_migration.ps1 -GuildId "YOUR_DISCORD_SERVER_ID" -RollbackPath ".\backups\fc-discord-backup-YYYYMMDDTHHMMSSZ.json"
```

Применить откат:

```powershell
.\run_migration.ps1 -GuildId "YOUR_DISCORD_SERVER_ID" -RollbackPath ".\backups\fc-discord-backup-YYYYMMDDTHHMMSSZ.json" -Apply
```

Введите `ROLLBACK FC`. Откат восстанавливает имена, категории, позиции и разрешения прежних каналов, а также изменённые роли. Новые каналы и роли намеренно остаются на месте: автоматическое удаление могло бы уничтожить сообщения, появившиеся после миграции. При необходимости их можно удалить вручную после проверки.

## Важные границы

- Скрипт не публикует приветственные тексты и не назначает роли участникам.
- Discord Onboarding/Server Guide не меняется: его лучше включить вручную после миграции, когда структура проверена.
- Стрим-уведомления продолжит отправлять текущий `stream-bot`; после миграции проверьте в его настройках, что назначением стал `🔴эфиры`.
- Архивы скрываются от `@everyone`, но существующие точечные разрешения ролей и участников сохраняются. Это сделано, чтобы не отрезать бывших участников от их истории неожиданно.
- Не вставляйте токен в файлы, чат или скриншоты. Если токен когда-либо был опубликован, сразу нажмите **Reset Token** в Discord Developer Portal.
